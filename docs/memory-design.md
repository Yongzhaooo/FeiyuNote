## 1. 课程内复习记录试验（当前阶段实施规格）

### 1.1 业务目标与信息分类

在学习过程中，学生面对三类不同信息：
1. **课程知识**：定理、证明、例题、符号约定（适合有来源的课程知识库）。
2. **学习状态**：我对一致收敛仍有疑问；这道题已经理解（适合可修改的课程学习记录）。
3. **学习偏好**：先举例再证明；讲解简短一点（适合用户明确选择的设置）。

第一阶段先做**课程学习记录**的本地操作闭环，验证“记录卡在哪里、哪些题需要复习”对学生的实际帮助，避免盲目做全局记忆导致错误推断长期影响回答风格或上下文污染。

### 1.2 核心操作闭环（全部为本地显式操作，零模型调用）

1. **显式加入复习**：
   - 在 `COURSE` 类型的课程中，学生可在已完成的回答（Assistant 消息）或笔记（Note）上点击「加入复习」。
   - 弹出确认对话框：预填主题（Topic，默认截取关联问题/笔记标题）、用户疑问或重点说明（Notes）、来源条目编号（`#Entry ID`）。
   - 用户确认后保存一条课程复习记录。
   - **重复点击防护**：若同一来源已被加入复习且未删除，二次点击直接提示或复用现有记录，不重复插入多条重复记录。
2. **手工新增复习条目**：
   - 在课程复习列表支持点击「新增」，允许学生直接输入复习主题与重点说明，无来源条目标为“手动添加”，不伪造不存在的来源 ID。
3. **查看与状态标记**：
   - 课程复习列表中展示所有本课程的复习记录。
   - 状态为三档：`待复习 (PENDING)` / `已理解 (UNDERSTOOD)` / `仍有疑问 (CONFUSED)`。
   - 学生可随时点击切换状态。不给未经校准的数值掌握度，不打能力缺陷标签。
4. **编辑与删除**：
   - 支持编辑复习记录的主题与说明。
   - 支持删除复习记录。删除复习记录不影响原问答和笔记。
5. **回到来源**：
   - 带有来源的记录提供「回到来源」按钮，点击可直接跳转到对应课次并定位至原问答或笔记。
   - 若来源问答或课次已被删除，记录显示「来源已删除」，禁用跳转，防止误导。

### 1.3 严格隔离与数据不变量

1. **`notebookId` 硬隔离边界**：
   - 所有复习记录的插入、读取、修改、删除及来源校验必须在数据层严格核验 `notebook_id`。
   - 严禁跨课程关联来源，普通聊天（`GENERAL_ID`）和刷题本（`PRACTICE`）不建立课程复习记录。
2. **级联删除与来源失效处理**：
   - 删除课程（Notebook）时，外键级联删除其下所有 `review_records`。
   - 删除来源（问答所在的 Thread、Lesson 或单条笔记）时，不能保留可误导的有效引用。应用将关联记录显式标记为 `source_deleted = 1`，保留原有记录文本供复习，但明确标注来源已失效。
3. **不改变现有请求与模型调用**：
   - 普通 ASK、EXPAND、MISTAKE 及整理本课 QA 的请求次数、提示词和上下文组装保持现有逻辑不变。
   - 本阶段不向模型注入复习记录，不触发后台模型摘要。

### 1.4 数据存储与 SQLite Schema (VERSION=4)

数据库版本由 3 递增至 4，保留已有 v1→v2→v3 升级链。新增表 `review_records`：

```sql
CREATE TABLE review_records (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    notebook_id INTEGER NOT NULL REFERENCES notebooks(id) ON DELETE CASCADE,
    topic TEXT NOT NULL,
    notes TEXT NOT NULL,
    source_entry_id INTEGER,
    source_deleted INTEGER NOT NULL DEFAULT 0,
    status TEXT NOT NULL CHECK (status IN ('pending', 'understood', 'confused')),
    created_at INTEGER NOT NULL,
    updated_at INTEGER NOT NULL
);
CREATE INDEX idx_review_records_notebook ON review_records(notebook_id);
```

## 【延期设计与历史规划】两层记忆与跨项目全量方案

> 注：以下内容保留自初始规划设计，作为未来多层记忆（M1—M4）与模型生成复习资料的长期演进参考。**当前阶段不实施以下特性**。

## 2. 两层记忆与开关（延期参考）

| 层级 | 保存什么 | 示例 | 在哪里生效 |
| --- | --- | --- | --- |
| 全局记忆 GLOBAL | 用户明确保存的学习偏好、通用方法，以及从课程主动共享的知识摘要 | 喜欢先讲直觉再讲证明；已复习过特征值定义；线性代数中的正交投影方法 | 开启“全局＋本项目”的课程或刷题本 |
| 项目记忆 PROJECT | 当前课程/刷题本的定义与符号、教师约定、课程重难点、个人疑难点、学习进度、单课学习偏好、带条件的知识摘要 | 本课程内积对第一变量线性；老师强调一致收敛；我对交换极限条件仍有疑问 | 当前 notebook_id 内的不同课次和分支 |

每个项目提供三选一：`OFF`、`PROJECT_ONLY`、`GLOBAL_AND_PROJECT`。

## 3. 学生操作与模型交互（延期参考）

- 显式调用模型整理课程记忆候选（M3）。
- 跨课程共享条目与跨课知识调用（M1/M2）。
- “整理本课”生成融合重难点、提问分布与偏好的个性化复习资料（M4）。

## 4. 实施顺序（更新说明）

原定 M1—M4 路线现调整为：
- **阶段一（当前）**：课程内复习记录试验（本地操作闭环，SQLite v4，严格课程隔离，无模型调用）。
- **阶段二（后续视试验结果决定）**：在“生成复习资料”时显式引入课程复习记录参考；高频追问建议。
- **阶段三（长期评估）**：评估是否有必要扩展为全局记忆与跨课共享。
