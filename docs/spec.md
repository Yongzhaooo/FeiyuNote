# 肥鱼笔记产品约定

日期：2026-09-30（2026-10-01 修订）。状态：核心功能、0.2 离线公式与 0.3 多图附件已发布；产品行为以此为依据。

本文保留首版要求及 0.2、0.3 补充。[实施与验证记录](plan.md)负责架构契约与验收证据，不另建产品范围。

## 1. 产品目标

学生在安卓手机、平板或折叠屏上，按课程和课次保存问题，调用系统相机拍摄材料，通过 DeepSeek 获得讲解，再主动整理成本地复习笔记；刷题时用刷题本记录错题，获得错题讲解并标记掌握情况。

产品重点是支持可拍照的移动设备，并提供随手记录、保存和回看的方案。手机独立使用。工作数据保存在应用自己的目录。保持一个小应用，用成熟组件完成平台能力，自行实现学习流程。

## 2. 已对齐的边界

课程和刷题本统称笔记本，共用同一套结构和能力；下文“课程”条款同样适用于刷题本，差异在 S09 列出。

| 编号 | 首版要求 |
| --- | --- |
| S01 | 同一套界面和业务支持手机、平板、折叠屏，以及应用窗口大小变化。窄窗口单栏，空间足够时列表和详情双栏。 |
| S02 | 按笔记本、课次组织内容；SQLite 保存文字和关系，本地文件保存图片，均使用应用私有目录。打开应用直接回到上次打开的课次；新建课次默认以当天日期为标题。 |
| S03 | 基础模型接入为用户自己的 DeepSeek API，在设置中修改 Key（独立的密钥页）和模型名，接口地址固定。所有生成动作共用一个请求入口。 |
| S04 | 拍照调用系统相机，或通过系统照片选择器从相册一次选择多张图片，返回后逐张预览、移除附件；用户发送时才调用模型。同一课次可以连续多次拍照或选图提问，数量不设上限；单条提问可附多张照片，继续拍照或选图会追加附件。只有照片没有文字时，按内置“识别并讲解”指令发送。 |
| S05 | 提问、追问、展开讲解、错题讲解、整理本课均由用户主动触发。回答和笔记以可读文本展示，公式按下述 0.2 规则渲染。 |
| S06 | 整理结果作为可编辑笔记保存，保留对应问答来源；已有内容可以离线阅读；单条笔记可保存为 HTML 文件或通过系统分享发出。 |
| S07 | 保存追问的父消息关系；按当前问答路径、用户勾选的本链照片和用户选定的参考笔记提供上下文。 |
| S08 | 旋转、折叠和布局重排不重复发送请求、不丢当前草稿；请求失败或中断不损坏已保存内容。 |
| S09 | 可以创建刷题本，可选关联一门课程。一道题是一条带照片的根提问；题目有“未掌握/已掌握”状态并可筛选；刷题本内提供“错题讲解”动作。 |
| S10 | 讲解模板：用户可创建、编辑、删除模板（名称和指令文字）；笔记本可设默认模板，提问时可临时换一条。 |
| S11 | 问答线程（一条根提问及其全部追问）可归档、恢复和删除；笔记、课次、笔记本可删除，删除前确认。 |

0.3.1 增加：首页固定“公共聊天”，无需课程即可连续聊天（自动接续最近一条已完成回答，使用通用助手提示词，模板与参考笔记照常可用）；设置页可选择界面语言（中文/英文/跟随系统）、日夜主题和字号，可测试连接（仅认证调用 `GET /models` 并刷新模型列表，不发起生成）。默认模型与推理强度在设置页修改，每个会话可单独覆盖或恢复默认。问答编号按会话内提问创建顺序显示，提问 N 的回答、重试均为 N，不显示数据库 ID；长会话右侧提供跳转节点，跳转只滚动列表，不发请求、不丢草稿。首页公共聊天以带“一起来聊天吧”标签的卡片呈现；欢迎卡片与公共聊天卡片插图可在设置中替换或恢复默认，图片只存本机。预装“引导式讲解”模板（可编辑、可删除），新建笔记本默认选用；已有笔记本与公共聊天不受影响。设置的“高级”区默认收起：可修改学习助教、公共聊天、整理本课三段内置系统提示词（清空或恢复默认即还原）；可通过 GitHub 链接安装 Skill——仅接受 https 的 github.com / raw.githubusercontent.com，读取不超过 64 KB 的 SKILL.md 文字，预览确认后保存为带来源标记的讲解模板。Skill 不作为运行框架：不下载、不执行其中的脚本或其他文件，界面须向用户说明 Skill 是什么及其文字会发送给 DeepSeek。

0.2 增加原生离线 LaTeX 公式渲染：对话、笔记阅读与 HTML 导出共用解析与渲染，支持 `$...$`、`\(...\)`、`$$...$$`、`\[...\]`，保留可编辑、可复制原文；失败时显示原文，宽公式横向滚动。不支持完整 TeX 文档、自定义宏或外部资源。当前版本不引入 WebView 阅读器、Room、OpenCode 运行时、RAG、通用 agent/skill/插件运行框架、自建相机、云同步或完整备份系统。讲解模板只是一段附加指令，不执行代码、不加载资源。Skill 的长期扩展方向见[后续方向](#10-后续方向)。

API Key 使用 Android Keystore 中不可导出的 AES-256 密钥和 GCM 认证加密，密文保存在应用私有目录；禁止备份/设备迁移该凭据；唯一输入 Key 的密钥页（设置 › DeepSeek 密钥）禁止普通截屏和录屏。release 不可调试；密文损坏或密钥丢失时要求重新输入。安全测试使用独立的合成凭据，不读取用户真实 Key。

首版不要求流式输出、多供应商管理、学科分类、自动课程摘要、自动整理、待复习标记、知识卡片、间隔复习、图谱画布、动画、PDF 或专用悬停模式。这些均不作为验收条件。

不再做模型效果评测或课堂样本对比，不把它们作为开工前提。接口、存储和设备交互的工程验证仍需完成。

## 3. 界面和设备行为

采用 Kotlin、Jetpack Compose、Material 3 Adaptive 和 Navigation 3。列表与详情使用官方的 ListDetailSceneStrategy 组织，共用同一套页面和选择状态。

| 场景 | 行为 |
| --- | --- |
| 窄窗口 | 显示笔记本/课次列表或当前详情，按正常返回操作切换。 |
| 宽窗口 | 左侧为当前层级列表，右侧为会话或笔记；详情文字保持适当宽度。首版最多双栏。 |
| 展开、折叠、旋转、分屏调整 | 根据当前窗口尺寸重新排列内容，保留选中笔记本、课次、草稿和阅读位置。 |
| 系统报告折叠分隔区域 | 使用官方自适应布局信息避开遮挡和分隔区，不按设备型号写规则。 |
| 软键盘出现、外接键盘输入 | 输入框可见、可编辑，按钮可以获得焦点；不额外建设快捷键系统。 |

导航和内容区域分开。页面 ViewModel 只持有选择、草稿和待发送附件，SavedStateHandle 和可保存的列表状态负责必要的界面恢复。生成请求由应用进程级的单一执行者持有，结果写入数据库；页面观察数据库和执行状态，不从重绘过程发起请求，也不因页面或 ViewModel 销毁而取消请求。上次打开的课次 ID 存于应用私有设置。

笔记本列表分“课程”和“刷题本”两组。课次内默认只显示未归档线程，另有“已归档”入口；刷题本的课次可按掌握状态筛选题目。

## 4. 学习流程

1. 打开应用回到上次课次；或创建/打开笔记本，创建或继续一个课次。刷题本的课次可命名为章节或试卷。
2. 输入文字，或调用系统相机拍照，或从系统照片选择器多选图片。图片追加到当前提问，逐张预览和移除；导入期间显示进度提示并禁止发送，失败图片清理临时副本并提示，其余已选图片保留。取消选择不改变已有附件，不请求整个相册的读取权限。
3. 点击发送，先保存提问，再调用 DeepSeek。等待时可取消；完成后保存回答。
4. 对选中的回答发起追问或点击“展开讲解”，保留来源关系，复用同一个请求入口。追问默认只发文字；可打开“附上原图”，按本条问答链中的提问勾选要附带的原图，每组显示图片数量。
5. 刷题本中，在题目下写下或拍下自己的解答，点击“错题讲解”：模型对比该解答指出错因并给出正确解法。新题默认“未掌握”，由用户手动切换。
6. 点击“整理本课”，使用本课未归档、已完成的问答生成一条笔记。只在成功后新建笔记，允许编辑；失败或取消不写笔记；再次整理产生新笔记，不覆盖已有版本。
7. 阅读已有笔记，编辑后保存；通过系统文件保存界面导出，或用系统分享发出。

所有生成操作均显示等待、成功或失败状态。切换布局、保存编辑、退出页面不触发额外生成。首版同一时刻只执行一个生成请求；当前请求完成或取消后才能再发起。请求进行中切换课次或返回上层不会取消它，结果仍写入发起时的课次。

生成有两条落库路径：

- 提问、追问、展开、错题讲解：发送时在一个事务中保存 user 条目和 pending 的 assistant 条目，完成后更新该 assistant 条目的正文和状态。
- 整理本课：不预先写任何条目，只在执行者中保持运行状态；成功后在一个事务中新建 note。失败、取消或进程重启都不留下 note 或 pending 记录。

生成与删除并发时：删除操作若涉及当前生成目标（该 assistant 条目、它所在的线程、课次或笔记本），先取消该请求。结果提交前在同一事务中复核目标仍存在、仍为 pending（整理则复核课次仍存在）；目标已不存在时丢弃结果，不重新插入已删除内容。已经到达的迟到响应同样遵守这条复核。

本地资料和讲解模板中的内容是学习材料或讲解要求，不作为执行系统操作的指令。应用没有自动执行脚本、终端或模型工具的能力。

## 5. 数据与文件

全部笔记本共用一个 SQLite 数据库，图片按笔记本稳定 ID 分目录存放；修改显示名称不移动目录。笔记本隔离由查询条件保证，不靠拆分数据库文件。数据库和图片使用相对关联，不将供应商响应对象直接作为持久数据模型。

示意路径：

    databases/
      notes.db
    files/
      images/
        <notebook-id>/

数据库使用 Android 内置 SQLite，包含笔记本、课次、内容条目和讲解模板四张表；不为“消息”“笔记”“记忆”分别创建引擎。

| 数据 | 最小字段 |
| --- | --- |
| Notebook | id、kind、name、linkedCourseId、defaultTemplateId、createdAt |
| Lesson | id、notebookId、title、createdAt |
| Entry | id、lessonId、kind、action、text、parentEntryId、sourceEntryIds、imagePaths、attachedImageEntryIds、templateId、state、archived、mastery、createdAt |
| Template | id、name、instruction、createdAt |

- Notebook.kind 为 course 或 practice。linkedCourseId 只用于刷题本，可空，指向一门课程。defaultTemplateId 可空。
- Entry.kind 为 user、assistant 或 note。parentEntryId 用于问答路径；sourceEntryIds 记录整理来源（note）和参考笔记（user），只需从条目正向查到来源，以 JSON 文本列保存。可空字段不需要为每条记录填充。
- Entry.action 只用于 user 条目，取值为 ask、expand 或 mistake；重试时据此重建同一动作。templateId 记录该次提问实际使用的模板，可空。
- imagePaths 只用于 user 条目，按附件顺序保存多个应用生成的相对文件名，以 JSON 文本列保存。数据库 v2 将旧 image_path 自动迁移为单元素列表，保留原照片与条目关系。attachedImageEntryIds 记录追问时勾选的本链提问条目；每次勾选附带该条目的全部照片，界面标明图片数量。
- state 只用于 assistant 条目，取值为 pending、complete、failed、cancelled 或 interrupted；user 和 note 条目写入即完成。
- archived 和 mastery 只用于线程的根 user 条目。mastery 只在刷题本中使用，取值为 unmastered 或 mastered，新题默认 unmastered。

已提交的提问独立保存；失败和取消不能删除它。生成请求只存在于应用进程内，因此进程启动时把所有 pending 记录标记为 interrupted，不自动再次调用 API。用户主动重试时建立新的回答记录，保留原提问。

数据库记录通过事务提交。照片先成功写入文件，再提交引用；未写完或不存在的照片不能成为已发送附件。相机取消时只清理本次创建的空临时附件。相册图片通过系统照片选择器获取，无需存储权限；先完整复制到所属笔记本的图片目录并确认可解码，才成为待发送附件；应用不修改也不长期引用相册原文件。普通进程重启后能够读取已保存记录和图片。

归档与删除：

- 归档线程：从默认列表隐藏，可在“已归档”查看、恢复和离线阅读；“整理本课”不包含已归档线程。
- 删除线程：删除根提问及其全部后代条目和它们的照片。
- 删除笔记：只删该笔记。
- 删除课次：删除其中全部条目、笔记和照片。
- 删除笔记本：删除其全部课次、条目、笔记和图片目录；关联了该课程的刷题本解除关联。删除模板时，引用它的笔记本默认模板置空。
- 被删除内容若是某条笔记的来源，笔记正文保留，来源显示为“已删除”。
- 删除在一个数据库事务中提交，事务成功后再删除对应图片文件；图片删除失败只留下无引用的文件，不影响数据一致性。

archived 和 mastery 由存储写入入口保证约束：只能设置在根 user 条目上，mastery 只能设置在刷题本的条目上；违反时拒绝写入且不修改数据。界面只负责不显示对应入口。

失效引用：删除或解除关联后，界面上缓存的选择不能直接进入下一次请求。发送和重试前都重新读取并校验所引用的内容。

| 失效引用 | 行为 |
| --- | --- |
| 上次打开的课次已被删除 | 清空该记录，启动时回到笔记本列表 |
| 已选参考笔记被删除，或刷题本解除了课程关联 | 清除当前选择；发送前重新检查参考笔记仍在允许范围内 |
| 已选或历史条目引用的模板被删除 | 历史条目显示“模板已删除”；已选模板失效时清除选择；重试时提示重新选择模板或不用模板，不静默换用其他指令 |
| 重试或追问所需的照片不存在 | 发送前说明缺少哪张照片，让用户重新选择；不悄悄改成纯文字请求 |

SQLite 的辅助文件由数据库管理，不通过拷贝单个 notes.db 文件实现运行中的备份。目录导入和恢复备份不在本次范围。

## 6. DeepSeek 与上下文

用户提供自己的 DeepSeek API Key，可在设置页修改模型名；接口地址固定。地址、默认模型名和图片压缩参数集中在模型客户端配置中，不分散到页面代码。

本次落地默认值为：

- endpoint：https://api.deepseek.com/chat/completions
- model：deepseek-flash（DeepSeek V4.1 Flash）
- reasoning_effort：low
- stream：false

推理强度对应官方三档 low/high/max，界面用滑动条选择，默认最低档 low。官方另接受 medium，但服务端按 high 执行，因此不单独提供。若 `/models` 返回某模型的 effort 档位，以返回为准；当前档位不在列表内时回到该模型的第一档。

这些值是实施默认，不是长期不可变的产品约束。2026-09-30 已按官方文档核对：deepseek-flash 支持图片输入（deepseek-v4-pro 不支持），单图上限 32 MiB，每图最多计 1024 token，图片只能出现在 user 消息中。实现时如协议变化再核对，不重新开展效果调研。API Key 通过 Android Keystore 保护后存于应用私有配置，不进入笔记本数据库、导出内容或日志。设置页可以读取当前模型名和“Key 是否已配置”，不读取 Key 明文。

上下文由应用确定：

- 提问与追问：当前课次中通向所选父消息的已完成问答路径的文字，以及本次提问。兄弟分支不自动混入。路径文字总长超过 60,000 字符时（0.3.2 起）只保留最近的部分，从最早的消息开始舍弃，保留部分总是从一条提问开始，避免长时间的公共聊天超出接口上限。
- 图片：本次提问自带的照片，加上用户在“附上原图”中勾选的本链照片；可选范围只限本条问答链。其余历史照片不发送。
- 错题讲解：与追问相同的路径和图片规则，本次条目的文字或照片是用户的解答，内置指令要求对比该解答指出错因并给出正确解法。
- 参考笔记：允许选择一条已有笔记一并发送。课程中可选本课程的笔记；刷题本中可选本刷题本和所关联课程的笔记。不自动检索，也不自动生成新的“记忆”。
- 整理本课：只发送本课未归档、已完成问答的文字，不附照片；保留消息 ID 和父子关系，输出 Q&A 复习文本及来源关联。笔记是纯文字，作为参考材料时也只发文字。
- 讲解模板：模板指令追加在内置动作指令之后。笔记本的默认模板只用于提问、追问、展开和错题讲解，提问时可临时换一条或不用；整理默认使用内置指令，用户可以手动选一条模板。

除刷题本引用所关联课程的笔记外，不同笔记本的数据互相隔离。生成提示要求使用普通可读文本；回答正文与供应商的其他返回字段分开处理。

图片按官方协议以 base64 data URL 放在 user 消息中发送，不做前置 OCR。相机原图保存在本地作为存档，供回看原始材料；发送前按长边缩放并压缩为 JPEG，以减少上传时间。

缺少 Key、认证失败、网络错误、额度/限流错误、空回答及超出接口限制都应给出可理解的失败状态；用户可以保留输入并主动重试，不自动切换模型或循环重试。

## 7. 内容展示与导出

普通正文使用标准文本组件，支持选择和复制；公式原生离线渲染并保留源码复制，图片显示在对应消息内。名词追问通过来源链接、返回上层和条目列表呈现，不绘制可缩放树图。

导出以单条笔记为单位，生成静态 HTML：应用转义笔记文本后套固定模板，内嵌离线渲染的公式图片，写入笔记本名、课次标题和导出日期。用户可以通过系统文件保存界面写出，或通过系统分享发给其他应用。条目 ID 离开应用无意义，不写入导出文件。HTML 独立离线可读，不包含可执行脚本或外部资源网络依赖。

首版导出的是复习文本，不是包含原始照片的完整可恢复备份。来源关联只在应用内使用，可回到对应问答。

## 8. 验收

| 对应要求 | 必须观察到的结果 |
| --- | --- |
| S01 | 同一笔记本在窄屏为单栏、宽屏为双栏；旋转、展开和分屏调整后仍停留在同一课次；分隔区域不遮挡主要操作。 |
| S02 | 创建两个笔记本及各自课次后重启应用，记录和照片仍可读取，并直接回到上次打开的课次；上次课次被删除后启动回到笔记本列表；改名不改变附件关联；新课次默认标题为当天日期。 |
| S03 | 本地模拟服务能收到正确文本/图片请求，模型名随设置变化；Key 缺失、401、429、断网和空正文不会损坏已有记录。 |
| S04 | 系统相机成功返回的图片可预览并发送；多选图片按顺序复制进私有目录后可预览、逐张移除并一起发送，取消选择保留已有附件；重建界面保留待发图片，继续拍照追加；损坏图片提示失败，其他图片仍可发送；旧单图记录升级后可读，多图重试完整发送，删除线程/课次清理全部图片；只有照片时请求带内置指令；同一课次连续完成至少三次拍照提问，每张照片关联各自的提问和回答，重启后仍对应正确；取消相机不创建提问、不调用 API；拍照过程中旋转仍关联原课次。 |
| S05 | 每次主动操作仅产生一次请求；旋转、折叠、页面重绘和保存笔记都不增加请求次数；请求中切换课次或返回上层后，回答仍写入发起时的课次。 |
| S06 | 整理请求只含未归档问答的文字、不含照片；整理生成新笔记并可编辑；重复整理不覆盖已有笔记；离线能阅读已存内容；导出 HTML 能在外部浏览器离线打开；系统分享能发出同一 HTML。 |
| S07 | 在具有两个追问分支的课次里，只发送选中分支的父链；追问默认不带图，勾选后只带所选的本链照片；所选参考笔记正确加入；整理来源可回到原消息。 |
| S08 | 等待中取消或失败后提问仍存在；重启后未完成请求显示中断而非自动重发；已有成功笔记不受失败写入影响；整理失败、取消或重启后不留下 note 或 pending 记录；模拟 API 延迟响应期间删除目标线程或课次，迟到结果被丢弃，已删除内容不会重新出现。 |
| S09 | 刷题本可关联或不关联课程；关联后参考笔记可选该课程笔记，不关联时只能选本刷题本笔记；新题为“未掌握”，切换后筛选结果正确；对课程条目或非根条目设置掌握状态被拒绝且数据不变；错题讲解请求包含用户解答并使用错题指令；课程中不出现错题讲解和掌握状态。 |
| S10 | 默认模板加入提问、追问、展开和错题讲解请求，不加入默认整理请求；临时换用的模板只影响本次请求；手动为整理选择的模板生效；删除模板后默认模板置空。 |
| S11 | 归档线程从默认列表消失、在“已归档”中可读并可恢复，且不进入整理；删除线程后其后代和照片一并消失；引用被删内容的笔记正文仍在、来源显示“已删除”；删除课次和笔记本后相应记录和图片不再存在；删除已选参考笔记、模板或照片后，下一次发送按失效引用表处理，不带入已删除内容。 |

## 12. 课程复习记录（试验）

本功能作为学习记忆的第一阶段试验，先做课程内的学习记录闭环：
- **入口与操作**：在 COURSE 类型的课程中，用户可在已完成的问答或笔记上显式点击「加入复习」，确认后保存；课程页提供「复习记录」列表，支持查看、编辑、标记状态、删除及「回到来源」。支持无来源的手工新增。
- **状态流转**：支持「待复习 (PENDING)」、「已理解 (UNDERSTOOD)」、「仍有疑问 (CONFUSED)」，不使用数值分或推断能力标签。
- **隔离与边界**：严格以 `notebookId` 隔离，课程删除级联删除记录；来源被删除时显式标记 `source_deleted`，不保留可误导的有效跳转。
- **纯本地闭环**：完全在本地 SQLite 完成，零模型调用，不影响现有的 ASK/EXPAND/MISTAKE/SUMMARY 生成逻辑。
